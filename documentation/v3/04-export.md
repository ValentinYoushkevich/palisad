## Скоуп

1. **Прайс-модуль**: хранение цен «вид × контейнер» + страница редактирования.
2. **Экспорт остатков** (CSV): что есть в наличии — для внутреннего учёта/сверки.
3. **Экспорт прайса** (CSV): позиции с ценами и наличием — файл, который владелец шлёт
   покупателям.

Онлайн-фичи (без офлайн-очереди, кнопки задизейблены офлайн). RBAC: owner/agronomist
(редактирование цен и выгрузки).

Вне скоупа: XLSX (CSV с BOM Excel открывает нормально), публичные ссылки, мультивалюта,
скидки/оптовые цены, интеграции с маркетплейсами.

## Связь с v2-роадмапом (v2-roadmap-proposal.md)

- Экспорт = этап 5.4 роадмапа; флаг `feature_export` подключается здесь (см. API ниже).
- `species_prices` — **цена предложения** (прайс-лист). Это НЕ цена сделки: этапы 5.3/8
  роадмапа (рентабельность, CRM) добавят фактическую цену продажи в движение типа «продажа»
  отдельным полем; `species_prices` тогда станет источником дефолта при оформлении продажи.
  Сущности не конфликтуют — при этапе 8 ничего переделывать не придётся.

## Нюанс модели: сорт (variety)

`variety` — свободный текст на растении, не справочник. Поэтому:
- **прайс** — строго вид × контейнер (variety в позиции прайса нет);
- **остатки** — variety показывается как колонка группировки (по фактическим значениям).
Если сорта станут справочником (v4) — прайс расширится без миграции смысла.

## Модель данных (1 миграция, обратимая; schema.sql синхронно)

### `species_prices`
- `id` UUID PK, `nursery_id` UUID NOT NULL FK CASCADE
- `nursery_species_id` UUID NOT NULL FK CASCADE
- `container_type_id` UUID NOT NULL FK CASCADE (свой или системный контейнер)
- `price` NUMERIC(10,2) NOT NULL CHECK (price >= 0) — BYN
- `created_at`/`updated_at`
- UNIQUE (`nursery_id`, `nursery_species_id`, `container_type_id`)
- составной FK принадлежности вида питомнику — по образцу D2/D15 (`(nursery_species_id,
  nursery_id) → nursery_species(id, nursery_id)`); контейнер валидируется в сервисе
  (системные строки с `nursery_id IS NULL` — как в B5).

## API

```
GET    /api/nurseries/:nurseryId/prices            список цен (join вид+контейнер)
PUT    /api/nurseries/:nurseryId/prices            upsert { speciesId, containerId, price }
DELETE /api/nurseries/:nurseryId/prices/:id        убрать позицию из прайса
GET    /api/nurseries/:nurseryId/exports/stock     ?groupBy=species|location&format=csv
GET    /api/nurseries/:nurseryId/exports/price-list ?includeUnpriced=true|false&format=csv
```

- Всё под `requireAuth` + `requireNurseryAccess` + `requireRole(...STRUCTURE_ROLES)`.
- Оба экспорта гейтятся планом: `checkFeature(accountId, 'feature_export')` → 403 при плане
  без экспорта (колонка `plans.feature_export` уже в схеме; заложено v2-роадмапом, этап 5.4).
  Управление ценами (`/prices`) НЕ гейтится — гейт только на выгрузку файлов.
- `PUT` — upsert по UNIQUE-тройке (`onConflict().merge()`), цена=null не бывает — снятие
  позиции только DELETE.
- Экспорты стримятся (`Content-Disposition: attachment`), CSV: UTF-8 **BOM**, `;`,
  экранирование — общий `toCsv` (см. 01-reports).

### Экспорт остатков (`stock`)

Активные растения (`deleted_at IS NULL`, статус `growing`/`storage`), агрегат:
`groupBy=species` (default): вид | сорт (variety) | стадия | контейнер | количество.
`groupBy=location`: + колонка локации (полный путь «Участок / Секция / Ряд»).
Сортировка: вид → контейнер. Итоговая строка «Всего».

### Экспорт прайса (`price-list`)

Join остатков (по виду×контейнеру) с `species_prices`:
колонки: вид (научное + локальное имя) | контейнер | в наличии, шт | цена, BYN.
- default: только позиции **с ценой и наличием > 0** — готовый файл покупателю;
- `includeUnpriced=true` — плюс позиции с наличием без цены (пустая колонка цены) — режим
  владельца «найти дыры в прайсе»;
- шапка файла: название питомника, дата выгрузки, «Цены в BYN».

## Frontend

- `stores/prices.store.js` — цены + ошибки; офлайн — заглушка.

## Тесты (ключевые)

- upsert: создание/обновление цены, UNIQUE-тройка не даёт дублей; отрицательная цена → 400;
- изоляция: цены чужого питомника не видны/не редактируются (404), вид чужого питомника в
  PUT → 404, системный контейнер в PUT → 201;
- остатки: агрегация по вид×сорт×стадия×контейнер, groupBy=location путь локации,
  проданные/списанные/удалённые исключены;
- прайс: join корректен, фильтры default/includeUnpriced, «Всего» и счётчики;
- CSV: BOM, `;`, экранирование кавычек/`;` в названиях видов, Content-Disposition, стрим;
- RBAC: worker/observer → 403 на всё.

## Критерии приёмки

- Прайс-CSV открывается в Excel (RU-локаль) без кракозябр и разъезжания колонок; цены с
  двумя знаками.
- Владелец за ≤ 3 клика получает файл, готовый к отправке покупателю.
- Изоляция tenant'ов покрыта тестами; покрытие ≥ 90/80.
