# Палисад — общий обзор проекта

## Что это за проект

**Палисад** — PWA-приложение (offline-first веб-приложение) для учёта питомников растений.
Позволяет вести полный учёт каждого растения: от посадки до продажи — местонахождение,
история операций, движения, жизненный цикл, фото и заметки.

Приложение рассчитано на работу «в поле» без устойчивого интернета (офлайн-режим с
последующей синхронизацией).

**Целевая аудитория** — владельцы и агрономы питомников декоративных, плодовых и
смешанных растений. Старт — рынок Беларуси, далее — Россия и СНГ.

**Монетизация** — SaaS-подписка по модели freemium: базовый функционал бесплатно,
расширенные возможности (теги, операции, QR, фото, экспорт и др.) — по платным планам
(управляется через лимиты и фичи плана: `plant_limit`, `user_limit`, `feature_tags`,
`feature_operations`, `feature_qr`, `feature_photos`, `feature_export`).

## Роли пользователей

| Роль | Права |
|------|-------|
| **Owner** (владелец) | Полный доступ. Управляет подпиской, сотрудниками, структурой питомника, всеми справочниками. |
| **Agronomist** (агроном) | Полный доступ к растениям, операциям, движениям, структуре и справочникам. Не управляет подпиской и сотрудниками. |
| **Worker** (работник) | Работает с растениями: операции, фото, заметки, движения, сканирование QR. Не управляет структурой и справочниками. |
| **Observer** (наблюдатель) | Только чтение: реестр, размещение, статистика, лента активности. |

## Ключевые возможности (MVP, v1)

- **Аккаунты и питомники** — регистрация, создание питомника, управление сотрудниками и ролями (RBAC), смена пароля.
- **Подписки и тарифы** — планы free/paid, лимиты (`plant_limit`, `user_limit`) и фичи-флаги, переключение плана.
- **Реестр растений** — карточка растения: вид (через GBIF), сорт, дата посадки, источник, статус, локация, тип контейнера, теги, заметки; QR-код и числовой код, поиск по ним.
- **Справочники** — виды (глобальный каталог `species_catalog` + привязка к питомнику `nursery_species`, интеграция с GBIF), типы контейнеров (системные P9/C1…C35/ОКС/Прикоп/Теплица/Холодильник + кастомные), типы движений (системные + кастомные), теги с цветом.
- **Структура питомника** — иерархия размещения: участок → секция → ряд → место; дерево локаций.
- **Жизненный цикл растения** — журнал операций (полив, обрезка, пересадка `transplant` со сменой контейнера и т.д.), фото, заметки, история.
- **Учёт движений** — поступление, продажа, списание, перемещение (+ кастомные типы); движения меняют статус и/или локацию растения.
- **QR-коды и этикетки** — генерация PDF-этикеток (одиночные / сетка 4×3) с QR-кодом, числовым кодом, видом, сортом, типом контейнера, датой посадки и локацией.
- **Лента активности** — хронологический журнал событий питомника с фильтрами; автоудаление записей старше 2 лет (cron).
- **Офлайн-режим** — полноценная работа в поле с уже существующими растениями без сети: локальное хранилище (IndexedDB/Dexie), очередь синхронизации, индикатор online/offline, разрешение конфликтов «сервер побеждает». Создание новых растений и видов — только онлайн.

## Отложено на v2

- Расчёт себестоимости растения/партии (материалы, труд, ресурсы, накладные расходы, естественный отпад).
- Полный производственный учёт по стадиям (`Propagation → Liner → Container → Field`).
- Отчёты и аналитика владельца, склад и зимовка, задачи и планирование, продажи и CRM, уведомления, несколько питомников на аккаунте.

## Технологический стек (кратко)

- **Фронтенд:** Vue 3, PrimeVue, Pinia, Vite, Workbox/PWA, Dexie.js (IndexedDB), zxing-js, pdf-lib, Tailwind CSS — подробнее в [`frontend-overview.md`](./frontend-overview.md).
- **Бэкенд:** Node.js (ESM) + Express, PostgreSQL + Knex.js, Argon2id, JWT, Zod, Winston, node-cron, pdfkit + qrcode, интеграция с GBIF API — подробнее в [`backend-overview.md`](./backend-overview.md).
- **Инфраструктура:** Docker Compose (PostgreSQL 16 + backend-контейнер), Postgres на порту `5433→5432`, backend — на `3100`.

## Принципы схемы БД

- `updated_at` во всех мутируемых таблицах, мягкое удаление (`deleted_at`) для `plants` и `operations`.
- CHECK-ограничения на статусы/роли/типы, partial-индексы для активных записей.
- `TEXT` вместо `VARCHAR(n)`, `JSONB` для `details` в `activity_logs`.
- Справочники: `movement_types`, `container_types`; виды хранят `gbif_id`/`scientific_name` из GBIF, сорт (`variety`) — на уровне растения.
