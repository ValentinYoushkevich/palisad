# Палисад — система учёта питомников растений

## О продукте

**Палисад** — PWA-приложение для управления питомниками растений. Позволяет вести учёт каждого растения от посадки до продажи: фиксировать местонахождение, историю операций, движения и жизненный цикл. Система работает офлайн в поле и синхронизируется при появлении сети.

Целевая аудитория — владельцы и агрономы питомников декоративных, плодовых и смешанных растений. Старт — рынок Беларуси, затем масштаб на Россию и СНГ.

Монетизация — SaaS-подписка (freemium). Базовый функционал бесплатно, расширенные возможности по платному плану.

## Роли пользователей

### Owner (владелец аккаунта)
- Регистрируется в системе, создаёт питомник
- Управляет подпиской
- Полный доступ ко всем данным питомника
- Добавляет сотрудников и назначает роли
- Настраивает структуру питомника (участки, секции)
- Просматривает все отчёты, статистику и ленту активности

### Agronomist (агроном)
- Полный доступ к растениям: создание, редактирование, операции, фото, заметки, теги
- Фиксирует движения и смену контейнеров
- Управляет структурой питомника и всеми справочниками
- Сканирует QR-коды в поле

### Worker (работник)
- Работает с растениями: добавляет операции, фото, заметки, движения
- Сканирует QR-коды в поле
- Не управляет структурой, справочниками и сотрудниками

### Observer (наблюдатель)
- Только чтение: реестр, размещение, статистика, лента активности

## MVP-срез (v1)

**Регистрация и питомник** — аккаунт, питомник, сотрудники, роли.

**Реестр растений** — одно растение = одна запись.

*Обязательные поля:* вид (через GBIF), сорт (свободный текст), дата посадки, источник (своё/куплено), статус, местонахождение, тип контейнера.

*Опциональные:* теги, заметки.

QR-код + числовой код на каждое растение. Поиск по обоим.

**Справочник видов и GBIF** — виды выбираются из GBIF. Хранится `gbif_id`, `scientific_name`, латинское название. Пользователь задаёт `display_name_ru`. Виды появляются в справочнике только при реальном использовании. Контроль дублей по `gbif_id` в рамках питомника.

**Сорт** — свободный текст на уровне растения. Система показывает предупреждение при дублировании, не блокирует.

**Справочник типов контейнеров** — содержит стандартные типы (P9, C1, C2, C3, C5, C10 и др.) и позволяет добавлять кастомные. Каждый тип имеет: код, описание, тип содержания (горшок/открытый грунт/прикоп/холодильник/теплица). Смена контейнера фиксируется через операцию `transplant` — история смен видна в журнале операций.

**Учёт движений** — системные типы: поступление, продажа, списание, перемещение. Плюс кастомные типы.

**Жизненный цикл** — журнал операций, история, фото, заметки.

**Размещение** — четыре уровня: участок → секция → ряд → место.

**Теги и фильтры** — теги с цветом (`#RRGGBB`). Фильтрация по виду, статусу, локации, тегу, типу контейнера, числовому коду.

**QR-коды и этикетки** — PDF для обычного принтера. На этикетке: QR-код, числовой код, вид, сорт, тип контейнера, дата посадки, локация. Форматы: single / сетка 4×3.

**Офлайн-режим** — полная работа с существующими растениями без интернета. Создание — только онлайн.

**Лента активности** — хронологическая лента событий с фильтрацией.

**Монетизация** — free / paid план.

## Отложено на v2

**Расчёт себестоимости** — автоматический пересчёт себестоимости партии/растения. Компоненты: стоимость посадочного материала, трудозатраты по операциям, стоимость материалов (горшки, субстрат, удобрения, СЗР), энергия и ресурсы (вода, электричество), общехозяйственные расходы (амортизация, аренда). Учёт естественного отпада: при гибели части растений накопленная себестоимость распределяется на оставшиеся. Привязка затрат к каждой операции и движению.

**Полный производственный учёт (стадии производства)** — стадии как отдельная сущность со своей логикой (Propagation → Liner → Container → Field). Привязка к себестоимости, нормам трудозатрат по стадиям, аналитика по производственному циклу. Разрабатывается вместе с расчётом себестоимости.

**Прочее v2:**
- Отчёты и аналитика владельца
- Склад и зимовка
- Задачи и планирование
- Продажи и CRM
- Уведомления
- Несколько питомников на одном аккаунте

## Офлайн-режим

### Принципы

Создание новых растений и видов — только онлайн. Офлайн предназначен для работы в поле с уже существующими растениями.

### Что синхронизируется перед выездом

| Данные | Стратегия |
|--------|-----------|
| Растения (id, QR, числовой код, вид, сорт, контейнер, локация, статус) | Полностью или по участку |
| Справочник видов | Полностью |
| Справочник локаций | Полностью |
| Справочник типов контейнеров | Полностью |
| Теги | Полностью |
| Типы движений | Полностью |

### Архитектура

**Service Worker (Workbox)** — `CacheFirst` для статики, `NetworkFirst` для API.

**IndexedDB (Dexie.js)** — локальная база. Мутации через `sync_queue`.

**sync_queue** — типы: `create_operation`, `update_operation`, `delete_operation`, `create_movement`, `delete_movement`, `attach_photo`. Поля: `type`, `payload`, `timestamp`, `retries`, `status`.

При конфликте — серверная версия побеждает, пользователь получает уведомление.

### UX

- Индикатор онлайн/офлайн в хедере
- Кнопка «Синхронизировать сейчас»
- Иконка статуса на каждой записи
- При `retries >= 3` — уведомление с предложением повторить

## Лента активности

Хронологическая лента событий питомника, все роли. Хранение 2 года, автоудаление cron-джобой.

## Принципы схемы БД

- `updated_at` во всех мутируемых таблицах
- Мягкое удаление (`deleted_at`) для `plants` и `operations`
- CHECK-ограничения на статусы, роли, типы
- Partial-индексы для активных записей
- `TEXT` вместо `VARCHAR(n)`
- `JSONB` для `details` в `activity_logs`
- Типы движений в справочнике `movement_types`
- Типы контейнеров в справочнике `container_types`
- Виды хранят `gbif_id` и `scientific_name` из GBIF
- Сорт (`variety`) на уровне растения, не в справочнике видов
